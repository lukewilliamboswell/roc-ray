# Asset stores

`Assets.Store` is the disk-asset boundary for roc-ray applications. Open one
in `App.init`, retain it in the model while runtime-selected disk assets may be
loaded, and address all disk assets with portable store-relative names:

```roc
assets = Assets.Store.open!(
    Assets.with_manifest(Assets.beside_executable("assets"), {
        asset_set: "screwbot",
        schema: 1,
        content_version: 4,
        content: Sha256("0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"),
    }),
)?

font = Draw.load_store_font!(assets, { path: "fonts/Inter-Regular.ttf", size: 32 })?
floor = Assets.load_texture!(assets, "textures/floor.png")?
shader = Draw.Shader.from_store!(assets, { vertex_path: "", fragment_path: "shaders/floor.fs" })?
```

Use `Assets.beside_executable("assets")` for a packaged application,
`Assets.working_directory("assets")` only when CWD is intentionally part of a
development/tool workflow, and `Assets.absolute_directory(path)` for a
user-selected external/mod directory. None changes process CWD. The host opens
the root directory once and every subsequent load is resolved from that open
handle, so an unrelated launch directory cannot break a packaged app.

## Manifest contract

When requested, the root must contain `roc-assets.manifest` in this compact
line-oriented format:

```text
# Generated by packaging/CI, or maintained by the application.
asset_set = "screwbot"
schema = 1
content_version = 4
content_sha256 = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

`asset_set`, `schema`, and `content_version` are required by
`RequireManifest`. Set `content: AnyContent` when the declared digest is not a
startup requirement, or `content: Sha256(hash)` to require a syntactically
valid 64-hex-character expected digest. `Sha256` is validated before any I/O;
the manifest's `content_sha256` must then match case-insensitively.

This comparison is intentionally **not** a verification of loose files. It
reads only manifest bytes, so startup cost is independent of the number of
assets. A manifest declaration proves the selected asset-set identity and
declared content revision, not that every file still matches it after the
manifest was generated.

Packaging/CI generates the declaration with the included streaming tool:

```bash
python3 scripts/asset_manifest.py write assets/ \
  --asset-set screwbot --schema 1 --content-version 4
python3 scripts/asset_manifest.py check assets/ \
  --asset-set screwbot --schema 1 --content-version 4
```

It hashes a canonical sorted inventory of normalized `/` paths, file sizes, and
per-file SHA-256s, excluding `roc-assets.manifest` itself. Each entry is encoded
as `path + NUL + decimal-size + NUL + raw-file-sha256 + NUL` before the root
digest is calculated. Symlinks and
case-colliding/nonportable paths are rejected, and file contents are streamed.
A future manifest revision can retain that per-file inventory and let a store
verify an entry lazily when it is read. Full-tree verification is deliberately
an offline/package operation, not launch work. This first store implementation
has no hidden resource cache and no per-file integrity promise.

## Paths, errors, and runtime loading

Store-relative paths reject absolute paths, NUL, backslashes, `.`/`..`, empty
components, and trailing `/`. They use `/` on every platform, yielding one
canonical spelling per asset. The root handle prevents accidental
CWD dependence, but it is not a sandbox: an allowed symlink below the root may
resolve outside it. Use OS sandboxing or a later no-follow/confining store for
untrusted content.

Opening reports structured root/manifest errors (`RootNotFound`, `ManifestMissing`,
`ContentHashMismatch`, and so on) and the native host emits one clear stderr
diagnostic containing the resolved root when it was successfully opened (or the
configured root otherwise). Individual loads report
`AssetPathInvalid`, `AssetNotFound`, `AssetReadFailed`, or a resource-specific
decode error.

Texture, font, and shader store loaders are synchronous startup APIs. They
read into host memory, decode/compile/upload, then immediately release that
temporary buffer; no payload-sized file list crosses Roc. The store itself is a
typed ARC resource and stays open until its final Roc reference is released.
Runtime asynchronous asset tasks are intentionally a separate follow-up: they
need a typed `Task(msg)` completion ABI, worker admission budgets, and a main
thread GPU-upload lane. The `Store` handle is retained and typed so that work
can be added without replacing this API.

## Embedded authored assets

For a small, self-contained executable, compile-time file imports can use
`Assets.texture_from_bytes!`, `Draw.font_from_bytes!`, and
`Draw.Shader.from_source!`. The host borrows the `List(U8)`/`Str` during the
synchronous decode or compilation and retains only the resulting typed GPU/font
resource. Disk stores remain the right choice for large collections, mods,
downloaded content, and hot-reload workflows.
