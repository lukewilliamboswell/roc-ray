[#overview]
= What RocRay is

RocRay lets you build native games, visualizations, creative tools, and other
interactive programs in https://www.roc-lang.org/[Roc]. It is powered by
https://www.raylib.com/[raylib], and it runs on macOS (Intel and Apple
silicon), Linux x86-64, and Windows x86-64.

RocRay is a focused app platform, not a game engine. Your app keeps its own
state and rules. RocRay provides drawing, audio, keyboard, mouse and gamepad
input, windows, recording, files, networking, and a few other services, and it
calls your app once per frame. It does not give you a scene graph, an entity
system, or an editor; build those in Roc, or use a package, if your app needs
them.

== What you write

A RocRay app is three functions:

* `init!` runs once. It chooses the window options, loads what the app needs,
  and creates the starting state, which RocRay calls the _model_.
* `update!` runs once per frame. It receives the model and what happened since
  the last frame -- keys pressed, the mouse moving, work that finished -- and
  returns the next model.
* `render!` draws the model on the screen.

Reading a file or waiting for a network reply can take longer than a frame.
That work runs as a _task_, so the app keeps updating and drawing while it
waits; when the task finishes, its result arrives in a later `update!`.

<<app-model>> explains these pieces properly. You do not need to understand
them to run your first example.

== What an app can reach

Every app can draw, read input, play audio, print to its terminal, and record
itself. Reaching further -- a network service, a directory, another program,
an environment variable, the clipboard -- is written into the app's startup
configuration, so what an app can reach is visible in its source.
<<permissions>> explains how.

== Stability

RocRay follows Roc's new compiler closely, and its APIs may still change as the
language evolves. Each release names the exact Roc compiler it was built and
tested with. Bug reports, documentation improvements, approachable APIs, and
focused capabilities are welcome; see <<contributing>>.
