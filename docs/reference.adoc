[#reference]
= Reference

This chapter collects facts to look up: where the API reference lives, the
switches and environment variables every built app understands, the platform's
fixed limits, and the supported targets.

== API reference

The {api}[API reference] documents every module, type, and function the
platform exposes, generated from the platform's own module documentation. Each
effect's entry says which phases it is legal in (see <<phases>>). A release
publishes the reference for its version; its index opens the latest.

== Supported targets and bundles

Each release publishes two platform bundles that expose the same API:

[cols="1,3",options="header"]
|===
|Bundle |Use it for
|Default |macOS on Intel and Apple silicon, Windows x86-64, and Linux x86-64 through raylib's X11 build (which also runs under XWayland)
|Wayland |Linux x86-64 Wayland systems, when you want raylib's native Wayland build
|===

ARM Linux is not currently included. The release notes name each bundle's URL
and the exact Roc compiler the release supports.

[#reference-switches]
== Host switches

A built app accepts these switches. They all begin with `--host-`; the host
removes them before the app reads its arguments, and an unrecognised
`--host-` switch stops the app. `--host-help` prints a summary.

[cols="2,3",options="header"]
|===
|Switch |Effect
|`--host-headless` |Run without a window, GPU, or audio device; nothing is drawn
|`--host-headless-frames=N` |Run headless and stop after N cycles
|`--host-frames=N` |Stop a real windowed run after N cycles
|`--host-hidden` |Open the real window hidden; still needs a display server
|`--host-keys=SCRIPT` |Hold keys on the cycles named, such as `3:S,4:LEFT+X,10:32`; a `~` suffix taps the key within the cycle, such as `3:ESCAPE~`
|`--host-text=SCRIPT` |Deliver typed text on the cycles named, such as `2:ab,3:c`
|`--host-debug-allocator` |In a Debug build, use Zig's stack-tracing allocator to diagnose leaks
|`--host-stats-record` |Record an Observatory capture; see <<observatory>>
|`--host-stats-output=PATH` |Choose the capture's path, and record
|`--host-stats-detail=LEVEL` |`summary`, `standard` (the default), or `full`
|`--host-stats-buffer-mib=N` |Recorder memory in MiB, 1 to 4096; default 32
|`--host-stats-max-mib=N` |Stop recording once the capture reaches this size; default 4096
|`--host-help` |Print a summary of these switches
|===

== Environment variables

[cols="1,3",options="header"]
|===
|Variable |Effect
|`ROC_RAY_TRACE_TASKS` |Print a trace line for each task as it is spawned, queued, parked, resumed, finished, and delivered
|`ROC_RAY_ALLOC_STATS` |Print one line per frame to standard error with the bytes and calls that frame allocated and freed, and how much belonged to `update!`
|===

== Limits

These bounds are part of the platform's behaviour. Each is documented, with
what happens when it is reached, on the corresponding page of the API
reference.

[cols="2,1,3",options="header"]
|===
|What |Limit |At the limit
|Tasks running at once |32 |Further spawns wait and start in submission order
|Input events per cycle |256 |The rest are discarded and `events_overflow` is set
|Typed codepoints per cycle |32 |The rest are discarded and `text_input_overflow` is set
|Gamepads sampled |4 |--
|`read_text!` file size |64 KiB |`TooLarge`
|`read_bytes!` file size |16 MiB |`TooLarge`
|Standard output and standard error queues |256 KiB each |`TooLarge` for one payload bigger than the queue, `BufferFull` for a full queue
|HTTP request deadline and response body |30 seconds, 8 MB by default |The request fails; configurable with `send_with!`
|HTTP redirects followed |3 |--
|SQLite connections and statements |8 and 64 |`TooManyConnections` or `TooManyStatements`
|SQLite query result |1,000,000 cells; 16 MiB of text and blob data by default |The query is refused, never truncated
|===
