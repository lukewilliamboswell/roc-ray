# Freedoom Phase 1 E1M1 extraction

`generated/e1m1/map.json` is a direct deterministic representation of the
classic Doom-format E1M1 lumps in Freedoom 0.13.0. Coordinates, heights, and
texture offsets are signed integer Doom map units. Thing angles are integer
degrees. Indices are zero-based. Flags, specials, tags, and thing types remain
raw Doom integer values so the application, not the asset tool, owns gameplay
interpretation.

The root contains `format`, `map`, `units`, `vertices`, `linedefs`, `sidedefs`,
`sectors`, `things`, `segs`, `subsectors`, `nodes`, `subsector_polygon_bounds`,
`subsector_polygons`, `blockmap`, and `reject`.
The principal records are:

```text
vertex   { x, y }
linedef  { start_vertex, end_vertex, flags, special, tag,
           right_sidedef, left_sidedef }
sidedef  { x_offset, y_offset, upper_texture, lower_texture,
           middle_texture, sector }
sector   { floor_height, ceiling_height, floor_flat, ceiling_flat,
           light_level, special, tag }
thing    { x, y, angle, type, flags, sprite_prefix }
```

`thing_coverage.json` and `THING_COVERAGE.md` audit all 292 map things across
49 editor types. Each row records its exact count, semantic kind,
gameplay/decorative/start classification, required sprite prefix, and current
spawn/presentation status. Generation requires the coverage and sprite tables
to have identical editor-type keys, rejects unknown or newly absent types, and
checks the total count. This makes ignored starts/decorations and unfinished
gameplay types visible rather than silently discarding them. Type 15 correctly
uses the `PLAY` dead-player family (as do the two bloody-mess variants), while
the live former human uses `POSS`.

Absent sidedefs and the Doom `-` no-texture marker are JSON `null`. BSP child
records explicitly say whether their index names another node or a subsector.
Node bounding boxes retain Doom's top/bottom/left/right order. The blockmap
contains its origin, dimensions, and one linedef-index list per cell. REJECT is
retained losslessly as a hexadecimal byte string.

Classic Doom SEGS only represent portions of real linedefs. BSP partition
minisegs are implicit, so joining a subsector's SEGS does not generally form a
closed loop. The extractor instead begins with the validated min/max rectangle
of all map vertices and recursively clips that convex polygon through every
NODES partition. A node's right child keeps the non-positive directed-line
cross product and its left child keeps the non-negative side, matching Doom's
point-side convention. Each leaf produces:

```text
subsector polygon { subsector, sector, points: List({ x, y }) }
```

The list is in subsector-index order and its points are counter-clockwise.
Coordinates remain exact rational numbers during clipping; integral results are
JSON integers and fractional results are rounded to nine decimal places only at
serialization. Extraction fails unless every node and subsector is reached
exactly once, every polygon has at least three points with positive convex
turns, and all real SEGS in a subsector resolve through their direction-selected
sidedefs to one sector. `subsector_polygon_bounds` records the rectangle used to
close otherwise unbounded outer BSP leaves; it is a rendering boundary, not an
additional Doom map wall.

`world_atlas` contains all 114 wall texture names referenced by E1M1, composed
from `TEXTURE1`/`TEXTURE2` and `PNAMES` patches with palette zero from
`PLAYPAL`, plus all 44 referenced 64×64 flats. Entry keys are
`texture/DOOMNAME` or `flat/DOOMNAME`.

Both atlas metadata files use a deterministic `entries` list rather than a JSON
object with dynamic field names. Every entry has `name`, `kind`, `doom_name`,
and `rect: { x, y, width, height }`. World names retain the qualified
`texture/` or `flat/` prefix. Sprite entries additionally have `sprite` (the
four-character family) and an `aliases` list. Each alias is
`{ frame, angle, mirrored }`; a second alias records Doom's convention that the
same pixels serve another viewing angle after horizontal reflection. Angle zero
means the image is used for every viewing direction.

`sprite_atlas` contains every sprite lump for each standard Doom sprite prefix
needed by the map's thing types, not merely the initial visible frame. It also
admits the presentation-only families needed during play: pistol and shotgun
first-person states and flashes, imp projectiles, barrel explosions, bullet
puffs, and blood. The resulting 413 sprite lumps span 46 prefixes and cover
monsters, rotations, animation, pickups, corpses, decorations, weapons and
effects. Player/deathmatch starts intentionally have no sprite prefix.

The same atlas contains 88 status-bar graphics decoded from the WAD: the bar,
large/small/gray digits, face states, key indicators, arms panel and percent
sign. They have `kind: "graphic"`, an exact `doom_name`, an empty `sprite`, and
no rotation aliases. Keeping them in the presentation atlas lets Roc perform a
single deterministic lookup without teaching the host WAD naming rules.

`sounds/` contains the strict gameplay set for E1M1: pistol and shotgun,
doors/platforms/switches, pickups, former-human, shotgun-guy, and imp
sight/active/attack/pain/death variants, player pain/death/contact responses,
imp projectile/explosion, and
barrel explosion. Each Freedoom DMX format-3 lump becomes mono unsigned 8-bit
PCM WAV without resampling. `manifest.json` lists deterministic records:

```text
gameplay sound { name, lump, path, sample_rate, sample_count,
                 source_sha256, wav_sha256 }
```

Logical names remain unique where Doom intentionally reuses a lump (the zombie
attack uses the pistol sound and keys use the item pickup sound). Extraction
fails explicitly if a required lump is absent, has an unsupported encoding or
rate, or declares a sample count inconsistent with its bytes; no sound is
silently substituted or omitted.

The extraction does not yet interpret linedef or sector specials, reconstruct
whole-sector polygons, triangulate flats, calculate gameplay collision, or
execute runtime BSP traversal. The thing-to-sprite table follows the standard Doom
editor-number contract used by Freedoom. The exact `D_E1M1` standard MIDI lump is retained as
`music/e1m1.mid` and deterministically rendered to `music/e1m1.wav` by the
project-authored procedural instrument bank. The bank rejects unknown programs
or percussion rather than substituting them. The manifest records the eight
used General MIDI programs, thirteen percussion notes, renderer description,
sample rate and both checksums. The music is attributed through
`attribution/CREDITS-MUSIC`. The upstream
credit identifies it as “Stanky Leg Specialist” by Lola “BlueWorrior” Harvey.
